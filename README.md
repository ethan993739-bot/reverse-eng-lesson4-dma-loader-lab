## 二、本课目标

一句话：**破解这个加载器，让它在本地无条件执行注入。**

对照有效账号的完整行为，把下面每一环都跑通，最终得到「无条件执行注入」的成果：

1. 用 `shaowen123 / shaowen` 登录，完整还原有效账号从点 Start 到内核就绪的每步动作，
   作为破解时的对照基准。
2. 还原服务控制链：`OpenSCManager` → `DeleteService` → `CreateServiceA` → `StartServiceA`，
   确认各选项背后对应的是同一份内核。
3. 分析选项引用的加密 `.cache`，弄清它怎么解密、怎么交给下面那一层。
4. 还原用户态打开通信口的路径，补齐 `\\.\KernelX` 这一缺口，让通信真正能用。
5. 破解掉所有前置校验，让加载器**不连 C2、不用账号、不看选项，也能无条件走完注入全流程**。

## 三、分析任务

围绕样本完成以下工作（方法与工具自选，以跑通为准）：

1. **登录对照**：用 `shaowen123 / shaowen` 登录，记录并还原登录成功后的动作链。
2. **服务链还原**：还原服务控制链的完整顺序，确认各选项与内核的对应关系。
3. **`.cache` 分析**：找到选项对应的 `.cache`，分析它的格式、解密方式与传递去向，
   把它接到后续那一层上。
4. **通信口还原**：还原用户态打开通信口的路径，补齐缺失环节，让通信可用。
5. **无条件注入**：把控制「是否注入」的前置条件全部去掉，让样本在本地无条件执行注入，
   并验证结果。

## 四、可参考的排查方向（仅供参考）

- 先做信息收集：字符串、节区、导入函数、相关关键词。
- 动态观察服务控制链每个 API 的调用与返回值。
- 对比各选项行为差异，判断背后是“同一份内核”还是“多份模块”。
- 推断 `.cache` 的结构与解密入口，还原它的传递链路。
- 检查用户态对通信口的打开行为，定位为什么 `\\.\KernelX` 不存在、如何补齐。
- 找到控制注入的那条条件分支，把它改到无条件通过，让流程一路走到注入完成。
