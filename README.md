# 逆向工程实战课 · 第四课 —— VMProtect 保护破解与无条件注入驱动（授权靶场）

> 同学们好，我是这门课的讲师。欢迎来到第四课。
> 前三课我们打好了基础，这一课上强度：样本是一个**加了 VMProtect 壳**的 Windows 加载器。
> 本课的任务只有一个——**分析并破解它的 VMP 保护，让加载器能够「无条件执行注入驱动」**。
> 也就是说，把样本里原本有条件限制的那条驱动注入路径，改成不依赖任何前置校验、直接跑通。

---

## 一、本课任务（作业目标）

围绕目录中的样本 `逆向实战课第四课-授权靶场.exe`，完成以下任务：

1. **确认 VMP 保护**：识别样本使用的 VMProtect 版本与保护形态（虚拟化 / 变异 / 常量加密）。
2. **定位关键校验**：在 VMP 虚拟化代码里找到「是否允许执行注入驱动」的条件分支。
3. **破解 / 绕过保护**：通过 patch 条件跳转、修正 VM handler 分支或直接改写关键字节，
   使加载器**无条件执行注入驱动**，不再受原校验限制。
4. **验证结果**：在隔离环境里确认被改后的样本确实无条件走通了驱动注入流程。
5. **产出报告**：按课堂模板提交「保护分析 + 破解方案 + patch 记录 + 验证截图」的完整报告。

> 一句话总结本课目标：**从「有条件的加载器」变成「无条件执行注入驱动」的过程，就是我们要
> 亲手完成的一次 VMP 破解实战。**

## 四、破解流程（按此顺序推进）

### 第 1 步：确认 VMP 保护特征

```powershell
# 1. 提取字符串，先看有没有 VMP 残留特征与驱动相关关键词
strings64 "逆向实战课第四课-授权靶场.exe" | Select-String -Pattern "vmp|\.sys|driver|service|\.exe|\\\\.\\|DeviceIoControl" | Out-File recon_strings.txt

# 2. 记录样本指纹
Get-FileHash "逆向实战课第四课-授权靶场.exe" -Algorithm SHA256
```

- 用 **DIE** 确认 `VMProtect(3.x)` 壳与保护标记。
- 用 **PE-bear** 查看节区，确认是否出现 `.vmp0` / `.vmp1` 等 VMP 专属节区。
- 观察入口点：VMP 加壳样本的 OEP 常被替换成 VM 入口，代码段大量 `push imm / ret` 与
  handler 跳转。

### 第 2 步：脱壳 / 反虚拟化（Devirtualize）

- 用 `ScyllaHide` 挂上反反调试，再让样本跑起来，找到真实 OEP。
- 对关键函数做**反虚拟化**：把 VM handler 还原回可读的逻辑，重点还原「校验 → 分支」这段。
- 若完整还原困难，采用**局部还原 + 内存断点**策略：只还原决定注入路径的那段 VM 代码。

> 课堂提示：VMP 不一定要整体脱壳才能破。我们的目标是「无条件执行注入驱动」，
> 所以只需定位并翻转那一个**关键分支**即可，优先做局部破解。

### 第 3 步：定位「是否注入驱动」的关键分支

在反虚拟化 / 调试过程中，重点盯住驱动注入相关的底层 API：

- 服务方式：`OpenSCManager` → `CreateService` → `StartService`
- 原生方式：`NtLoadDriver` / `ZwLoadDriver`（配合注册表 `HKLM\SYSTEM\CurrentControlSet\Services`）
- 设备方式：`CreateFile` 打开 `\\.\` 设备名 → `DeviceIoControl` 下发 IOCTL
- 反调试干扰：`IsDebuggerPresent` / `NtQueryInformationProcess` / 时间差检测

在这些 API 上下断点，回溯找到调用链里**决定是否继续执行注入**的那个条件跳转（可能已被
VMP 虚拟化成 handler 分支）。

### 第 4 步：破解 —— 让注入「无条件执行」

定位到关键分支后，任选一种方式改掉它：

1. **直接 patch 原始跳转**：把 `jz/jnz` 改成 `jmp`（或 nop 掉整段校验），使流程无条件落入注入分支。
2. **改 VM handler 分支**：在 VMP 虚拟机的 handler 里改条件码 / 分支目标，翻转判断结果。
3. **修正校验返回值**：让校验函数无条件返回「通过」，等价于去除前置条件。

> 目标明确：**原来「满足条件 → 才注入驱动」，改成「无论什么情况 → 都注入驱动」。**

### 第 5 步：验证「无条件执行注入驱动」

1. 在隔离虚拟机里先启动 **Process Monitor** 与 **DriverView**。
2. 运行改后的样本，确认：
   - 进程确实调用了 `NtLoadDriver` / `CreateService` + `StartService`，或打开了目标设备
   - 目标驱动被成功加载（`DriverView` / `sc query` 能看到对应驱动）
   - 换一个「本不满足条件」的运行环境再跑，注入依然无条件发生
3. 记录 patch 前 / patch 后的字节差异（`010 Editor` 对比 + 截图）。
