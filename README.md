## 二、本课目标

一句话：**对照有效账号的完整行为，把样本从登录、到驱动拉起、再到资源加载与通道建立的
全过程，在本地环境里无条件复现出来。**

具体拆成下面几件事，全部以你实机验证为准：

1. 还原有效账号登录后的完整动作序列，弄清从点 Start 到内核就绪之间每一环做了什么。
2. 按选项还原那条服务控制链（建 / 删 / 起），确认不同选项背后到底对应几份内核。
3. 分析选项所引用的那类加密资源包，弄清它的格式、解密方式与向下层传递的去向。
4. 还原用户态打开通信口的路径，搞清楚“驱动在跑”和“可以通信”之间还差哪些环节。
5. 在本地把上面每一层都跑通，最终得到一个和有效账号行为一致的**无条件复现结果**。

## 三、分析任务

围绕样本，完成以下工作（方法与工具自选，以能跑通为准）：

1. **登录对照**：用上面给的 `shaowen123 / shaowen` 登录，记录并还原登录成功后的动作链，
   作为本地复现的对照基准。
2. **服务链还原**：弄清服务控制链的完整顺序（建 / 删 / 起），确认各选项与内核的对应关系。
3. **资源包分析**：找到选项对应的资源包，分析它的格式、加密 / 校验方式、解密与传递去向。
4. **通信口还原**：还原用户态打开通信口的完整路径，定位缺失环节并想办法补齐。
5. **本地复现**：让样本在本地环境里把登录、驱动拉起、资源加载、通信建立这几层全部走通，
   产出和有效账号一致（甚至不受账号状态约束）的复现结果。

## 四、可参考的排查方向（仅供参考，不必照搬）

- 先用信息收集摸清样本的字符串、节区、导入函数与相关关键词。
- 动态观察服务控制链的每一个 API 调用，记录参数与返回值。
- 对比不同选项下的行为差异，判断它们背后是“同一份内核”还是“多份模块”。
- 针对那类加密资源包，推断其结构与解密入口，尝试还原传递链路。
- 检查用户态对通信口的打开行为，结合内核对象命名判断“服务在跑”与“通信可用”之间的距离。
- 任何环节卡住时，以「补齐这一环、让后续流程继续走」为目标去处理。
