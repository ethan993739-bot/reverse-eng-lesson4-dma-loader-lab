## 二、上一讲成果回顾（静态分析结论）

上一讲我们用 radare2 与 strings 完成了静态取证，结论如下，供本讲参考：

1. **壳结构**：`.text` / `.rdata` / `.data` / `.pdata` 均为纯虚拟节（文件内无原始数据），
   真实载荷集中在大可执行节 `.BKh`（约 22 MB，`0x68000060` 可执行 + 可读 + 非分页代码）。
2. **节名混淆**：`..\i` / `.f(` / `.BKh` 为壳重命名产物，是 VMProtect 的典型布局。
3. **导入削减**：可见导入仅约 15 个启动桩（`LoadLibraryA` / `GetProcAddress` /
   `GetModuleHandleA` / `HeapAlloc` 等）。`OpenSCManager` / `CreateService` /
   `DeleteService` / `StartService` / `DeviceIoControl` / `CreateFile` 等**均不在导入表**，
   说明它们是在运行时经 `LoadLibraryA + GetProcAddress` 动态解析的。
4. **字符串加密**：全文件仅 4 条可读字符串，无明文 URL / 域名 / `.cache` / `.sys`；
   仅在原始字节中泄露 `DMZ`、`BO6` 两个游戏选项片段。
5. **资源为空**：`.rsrc` 仅 512 字节，无有效资源目录，驱动文件并未内嵌在样本中。

> 结论：样本是 VMProtect 高强度打包，静态层只能确定壳结构与少量泄露片段；要还原
> SCM 链、`.cache` 解密逻辑、通信口创建过程，必须进入动态分析——这正是本讲的内容。

## 三、本讲学习目标

1. 学会对加壳样本做动态分析：下断点、抓运行时解析的 API、dump 内存。
2. 还原样本创建 / 删除 / 启动服务的完整过程。
3. 找到并分析样本运行时使用的数据文件及其解密逻辑。
4. 还原样本与内核 / 通信对象之间的交互过程。
5. 通过合理修改样本，验证分析结论，并让样本**脱离联网与账号，在本地独立、完整地运行起来**。

## 四、课堂练习

### 练习 1：运行时 API 解析观察

在 `LoadLibraryA` / `GetProcAddress` 处下断，运行样例，记录它运行时实际解析了哪些 API，
尤其是与服务、驱动、通信相关的那些，补全上一讲导入表中缺失的部分。

### 练习 2：服务交互过程还原

用测试账号登录并运行，观察并完整记录样例创建、删除、启动了哪些服务，还原这一串动作的顺序。

### 练习 3：数据文件分析

运行样例，找出它落地或读取的加密数据文件，分析这些文件的格式、解密方式，以及解密后的数据交给了谁。

### 练习 4：通信机制还原

观察样例如何与内核或通信对象交互，还原通信的建立过程，说明通信是否成功、中间经过了哪些步骤。

### 练习 5：完整流程还原

把练习 1–4 的结论串联起来，画出样例从启动到完成主要功能的完整流程图，标注每一层的衔接点。

### 练习 6：独立运行验证

对样例进行合理修改，观察其行为变化，验证你对加载流程的理解，并尝试让样例
**脱离联网与账号限制，在本地独立、完整地运行起来**。

> 练习中遇到任何现象都请如实记录并继续分析下去，不要跳过，直到把整条流程完整还原、跑通为止。
